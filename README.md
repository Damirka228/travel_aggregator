# Travel Aggregator

Backend-сервис на Go для подбора комбинаций авиабилетов и проживания в пределах бюджета. Пользователь указывает город вылета, бюджет и длительность поездки; API возвращает рекомендуемый вариант, самые дешёвые туры и варианты с наиболее высокой категорией отеля.

Проект демонстрирует работу с внешним API, PostgreSQL, двухуровневым кэшем и параллельным получением данных. Каталог отелей пока содержит демонстрационные предложения; бронирование и проверка наличия номеров не реализованы.

## Возможности

| Возможность | Реализация |
| --- | --- |
| Поиск туров | Объединение билетов и отелей, фильтрация по бюджету и длительности |
| Источники билетов | Travelpayouts API и таблица `destinations` в PostgreSQL |
| Параллельное получение данных | Запросы к источникам выполняются через `errgroup` |
| Кэш билетов | L1 в памяти процесса: 5 минут; L2 в Redis: 1 час |
| Регистрация и вход | Хэширование паролей через bcrypt, выдача JWT на 24 часа |
| HTTP-маршрутизация | Отдельный `Router` с `NewRouter` и `SetupRoutes`; middleware для request ID, логирования и восстановления после panic в HTTP-обработчике |
| Завершение работы | Обработка SIGINT/SIGTERM, ожидание текущих запросов и закрытие ресурсов |
| Диагностика | Структурированные логи, ротация файлов, опциональный pprof |

## Архитектура

Код разделён на слои. Обработчики принимают HTTP-запросы, use case собирает и ранжирует предложения, а репозитории обращаются к источникам данных. Интерфейсы репозиториев объявлены в `domain`; зависимости собираются в `cmd/app`.

| Директория | Назначение |
| --- | --- |
| `cmd/app/` | Конфигурация, сборка зависимостей, запуск и остановка приложения |
| `internal/domain/` | Модели, интерфейсы репозиториев, справочник IATA |
| `internal/usecase/` | Поиск и ранжирование туров, регистрация и вход |
| `internal/delivery/http/` | Роутер, разбор HTTP-запросов и формирование ответов |
| `internal/repository/` | Адаптеры PostgreSQL, Redis, Travelpayouts и каталог отелей |
| `internal/cache/` | Кэш в памяти и декоратор репозитория билетов |
| `internal/infrastructure/` | Логирование, хэширование паролей и создание JWT |
| `queries/` | SQL-запросы для генерации кода через sqlc |
| `migrations/` | Миграции схемы PostgreSQL |

При поиске данные PostgreSQL и внешнего API запрашиваются параллельно. Для внешнего API используется цепочка `L1 → L2 → Travelpayouts`: при попадании в Redis данные сохраняются в L1, при ответе API — в оба кэша. Ключ кэша учитывает город вылета.

## Локальный запуск

Понадобятся Go 1.26.6, Docker с Compose и установленный Goose CLI (`goose`). `sqlc` требуется только при изменении SQL-запросов или схемы и последующей генерации кода.

### 1. Получить проект и подготовить конфигурацию

```bash
git clone https://github.com/Damirka228/travel_aggregator.git
cd travel_aggregator
cp .env.example .env
```

В `.env` задайте `JWT_SECRET` и `TRAVELPAYOUTS_TOKEN`. Для секрета JWT можно использовать случайное значение, например сгенерированное командой `openssl rand -hex 32`.

| Переменная | Значение по умолчанию / пример | Назначение |
| --- | --- | --- |
| `PORT` | `8080` | Порт HTTP-сервера |
| `DATABASE_URL` | `postgres://travel:travel@localhost:5432/travel_aggregator?sslmode=disable` | Подключение к PostgreSQL; обязательная настройка |
| `REDIS_ADDR` | `localhost:6379` | Адрес Redis в формате `host:port` |
| `JWT_SECRET` | Задаётся пользователем | Обязательный секрет подписи JWT |
| `TRAVELPAYOUTS_TOKEN` | Задаётся пользователем | Обязательный токен Travelpayouts API |
| `ENABLE_PPROF` | `false` | Включает маршруты профайлера под `/debug` |

Для совместимости поддерживаются прежние имена `POSTGRESQL_STR` и `REDIS_URL`. Если указаны оба варианта, приоритет имеют `DATABASE_URL` и `REDIS_ADDR`. `REDIS_URL` также должен содержать адрес `host:port`, а не URL с протоколом.

Переменные окружения процесса имеют приоритет над `.env`. При запуске проверяются обязательные настройки и доступность PostgreSQL и Redis; на подключение выделяется до 10 секунд.

### 2. Запустить PostgreSQL и Redis

```bash
docker compose up -d
```

### 3. Применить миграции

После готовности PostgreSQL выполните:

```bash
make migrate-up
```

По умолчанию Makefile использует те же параметры базы, что и Docker Compose. Для другой базы передайте строку подключения явно:

```bash
make migrate-up DB_URL='postgres://user:password@host:5432/database?sslmode=disable'
```

Приложение не применяет миграции автоматически.

### 4. Собрать и запустить сервер

```bash
make build
./bin/app
```

Для разработки также доступна команда `make run`. При работе с процессом напрямую используйте собранный бинарный файл: SIGINT/SIGTERM должны поступать самому приложению.

## HTTP API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/destinations` | Подобрать туры |
| `POST` | `/auth/signup` | Зарегистрировать пользователя и получить JWT |
| `POST` | `/auth/signin` | Войти и получить JWT |
| `GET` | `/debug/pprof/` | Профайлер; доступен только при `ENABLE_PPROF=true` |

Поиск сейчас доступен без JWT. Регистрация и вход выдают токены, но middleware для проверки токенов и защищённые пользовательские маршруты пока не реализованы. Профайлер предназначен для разработки; при включении его маршруты не требуют авторизации.

### Поиск туров

```bash
curl 'http://localhost:8080/destinations?budget=300000&days=7&city=MOW'
```

| Параметр | Пример | Использование |
| --- | --- | --- |
| `budget` | `300000` | Максимальная суммарная стоимость; должен быть больше 1000 |
| `days` | `7` | Верхняя граница длительности поездки и множитель стоимости проживания |
| `city` | `MOW` | IATA-код города вылета |

Ответ содержит следующие поля:

| Поле | Содержимое |
| --- | --- |
| `best_tour` | Один тур с минимальным значением скоринга |
| `cheapest_tours` | До пяти туров по возрастанию суммарной стоимости |
| `longest_tours` | До пяти туров по убыванию звёздности отеля; историческое имя поля |

Каждый тур содержит `flight`, `hotel`, `total_price` и `description`. Общая стоимость рассчитывается как `flight.Price + hotel.Price × days`. Скоринг рекомендуемого варианта: `total_price − hotel.Stars × 2000`. Расчёты подразумевают цены в рублях; отдельного поля валюты пока нет.

### Регистрация и вход

```bash
curl -X POST 'http://localhost:8080/auth/signup' \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"example-password"}'

curl -X POST 'http://localhost:8080/auth/signin' \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"example-password"}'
```

При успехе обе ручки возвращают JSON с полем `token`.

## Завершение работы

После SIGINT или SIGTERM сервер закрывает слушающий сокет и ждёт завершения активных HTTP-запросов до 15 секунд. Затем закрываются пул PostgreSQL, клиент Redis и файл логов. Если ожидание истекло, HTTP-соединения закрываются принудительно, а процесс завершается с ошибкой. Повторный сигнал во время остановки возвращает стандартное поведение ОС и позволяет завершить процесс сразу.

Очистка ресурсов выполняется также при ошибке запуска. Повторный вызов `App.Shutdown` безопасен.

Тесты HTTP-обработчиков, бизнес-логики и кэша используют подставные репозитории. Проверки жизненного цикла приложения используют локальный HTTP-сервер и не требуют подключения к внешнему API или рабочей базе данных.

Для измерения бизнес-логики на 100 демонстрационных билетах:

```bash

```

Этот бенчмарк не измеряет задержки внешнего API, базы или Redis. Результаты зависят от оборудования и условий запуска; показатели RPS и SLA в проекте не заявляются.

## Текущие ограничения

| Область | Ограничение |
| --- | --- |
| Отели | Статический демонстрационный каталог; для неизвестного города возвращается шаблонное предложение |
| Билеты из PostgreSQL | Пока не привязаны к городу вылета; параметр `origin` не используется в SQL |
| Даты и проживание | Даты рейсов не возвращаются клиенту; стоимость отеля считается по запрошенному `days`, а не по фактическим ночам между рейсами |
| Сбои источников | Ошибка источника пропускается; пустая выдача пока не отличает отсутствие туров от отказа всех источников |
| Кэш | Нет объединения одновременных запросов при промахе и ограничения размера L1 |
| Бронирование | Сервис подбирает предложения; покупка билетов, бронирование отелей и оплата отсутствуют |
